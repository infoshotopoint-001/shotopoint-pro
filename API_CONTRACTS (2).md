# SYFM Newsroom: backend API contracts

The website is a static front end. The forms do not create a secure membership database or editorial workflow by themselves. Implement these routes in the Shoto Point Node/MySQL backend before public launch.

## 1. Membership registration

`POST /api/public/membership/register`

Content type: `multipart/form-data`

Form fields used by the page:
- `firstName`, `middleName`, `lastName`
- `dob`, `gender`, `membershipType`
- `phone`, `email`, `occupation`, `interests`
- `address`, `city`, `state`, `emergencyContact`
- `consent`
- `passport` (image file)

Successful response example:

```json
{
  "ok": true,
  "member_id": "SYFM-2026-00123",
  "status": "RECEIVED — AWAITING MEMBERSHIP REVIEW",
  "reference": "MEM-2026-00123"
}
```

The backend should validate required fields, normalise phone/email, check duplicate registrations, validate image MIME and size, scan uploaded files, store passport images privately, allocate a unique member number, record consent and return a confirmation reference. Never trust a member number generated by the browser as an approved membership ID.

## 2. News submission

`POST /api/public/news/submissions`

Content type: `multipart/form-data`

Fields sent by the page:
- `title`, `category`, `submissionDate`
- `author`, `email`, `location`, `tags`
- `summary`, `sourceUrl`
- `content` (HTML generated by the rich-text editor)
- `media` (zero or more uploaded image, video, audio or document files)

Successful response example:

```json
{
  "ok": true,
  "submission_id": "SUB-2026-00123",
  "reference": "SYFM-NEWS-00123",
  "status": "PENDING EDITORIAL REVIEW"
}
```

The backend must sanitise editor HTML using a strict allow-list, reject scripts/event attributes, validate URLs, enforce file-size and file-type limits, scan media, store files safely, record contributor consent, apply anti-spam/rate-limits and put submissions into a moderation queue. A contributor submission must never be published automatically just because the form was submitted.

## 3. News articles

`GET /api/public/news/articles`

Return an array or an object containing `articles`, `items`, `results` or `stories`. Article fields accepted by the page include:

```json
{
  "id": 123,
  "slug": "sample-story",
  "title": "Story headline",
  "excerpt": "Short summary",
  "category": "Politics",
  "image_url": "https://cdn.example.com/story.jpg",
  "content_html": "<p>Approved story body.</p>",
  "author_name": "Reporter Name",
  "published_at": "2026-11-04T08:00:00Z"
}
```

Only return published/approved articles from the public endpoint. Keep drafts and pending stories in authenticated admin routes.

## 4. External publisher headlines

`GET /api/public/newsroom`

Return attributed headline items with `source_name`, `title`, `published_at` and `url`. Use publisher-authorised APIs, RSS feeds or a licensed aggregator. Show attribution and link to the publisher's original page. Do not scrape publisher websites, reproduce complete articles or use protected logos without permission. Africa Magic TV may require a direct content-partner arrangement rather than a public RSS source.

## 5. Ticker and newsletter

- `GET /api/public/news/ticker`: return strings or `{ "title": "..." }` items.
- `POST /api/public/newsletter/subscribe`: accept `{ "email": "reader@example.com" }`, validate and store subscription preferences with consent.

## 6. Radio stream

Set `radioStreamUrl` in `newsroom-config.js` to the authorised HTTPS audio stream URL. Confirm cross-origin playback and hosting terms with the stream provider.

## 7. Security and privacy checklist

- Serve the site and API over HTTPS.
- Add CSRF protection where cookie-based authentication is used.
- Validate and sanitise every field server-side; client-side checks are not security controls.
- Limit upload size; scan files; store user media outside the public executable directory.
- Protect passport photographs and applicant details; restrict staff access and define retention/deletion policies.
- Add privacy notice and consent records.
- Add server-side rate limits, spam controls, audit logs and moderation permissions.
- Never expose database credentials, secret keys or private storage paths in JavaScript.
